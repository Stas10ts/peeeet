# Инструкция для GitHub Copilot

## Источник требований

Проект — MVP сайта покупки авиабилетов **«Быстрый билет»** (AI core Leonov).
Исходная доска требований: https://trello.com/b/SpGjN3Zo/ai-core-leonov

Файл `copilot-instructions (2).md` является приоритетным описанием требований.
Если код противоречит ему, прав этот файл с требованиями. Если в инструкции
чего-то нет, не придумывай решение — задай уточняющий вопрос.

## Текущее состояние

В репозитории пока есть каркас Python-сервиса для проверки фактических утверждений
ИИ и типизированные модели данных. Он не реализует MVP авиабилетов. Не считай
существующие модели, зависимости и API готовой реализацией сайта покупок и не
переноси сюда их терминологию.

## Цель MVP

Гость без регистрации за пару минут находит рейс, вводит данные пассажиров,
оплачивает заказ и получает электронный билет на экране и по email.

- Заголовок главной страницы: «Купите авиабилет за пару минут, без регистрации».
- Язык интерфейса и текстов ошибок: русский.
- Код, имена переменных и комментарии: английский.
- Основной стек для MVP: статический HTML/CSS и JavaScript без фреймворков,
  сборщиков и дополнительных библиотек, пока пользователь явно не попросит иное.
- Роли: покупатель-гость и продавец.

## Основной сценарий

Реализуй последовательность экранов:

1. **Поиск** — маршрут, даты, пассажиры и валидация.
2. **Результаты** — тестовые рейсы, сортировка по цене и изменение поиска.
3. **Данные пассажиров** — ровно по одной форме на каждого пассажира,
   контакты покупателя и согласие с условиями.
4. **Оплата** — единая итоговая сумма и только банковская карта для MVP.
5. **Подтверждение** — номер заказа, PNR, маршрут, пассажиры, сумма,
   PDF-билет, печать и повторная отправка письма.

На экранах 3–5 всегда показывай сводку рейса: маршрут, дату и время,
авиакомпанию и итоговую цену.

## Обязательные правила

- Переходы делай маленькими: по одному экрану или одному модулю за раз.
- Не переписывай файлы целиком без необходимости.
- Храни состояние рейса, пассажиров и заказа в одном месте и передавай его
  между экранами без потерь.
- Дублируй проверку на клиенте и сервере:
  сумма, цена, места и статус платежа проверяются только на сервере.
- Защищай создание заказа, оплату и отправку письма от повторных действий
  (`idempotency`).
- Не стирай введённые данные при ошибке и показывай понятное сообщение рядом
  с проблемным полем.
- Поддерживай фокус и работу с клавиатуры, обязательные подписи и мобильную
  адаптивную вёрстку.
- Номер карты, срок действия и CVC не хранить и не логировать.
- Ключи провайдера оплаты и SMTP хранить только в переменных окружения.
- Персональные данные пассажиров не писать в логи.
- Помечай тестовые данные явно как `mock` или `test`.

## Обработка крайних случаев

- Рейсы не найдены — без вида ошибки показать «Рейсов на эти даты не найдено»
  и кнопку «Изменить поиск».
- Оплата не прошла — показать понятную причину и «Попробовать снова», сохранить
  данные пассажиров и не выдавать билет.
- Цена изменилось — вернуть к результатам и не списывать устаревшую сумму.
- Места закончились — вернуть к результатам и не оформлять заказ.
- Письмо не дошло — оставить билет доступным по ссылке и добавить повторную
  отправку письма.

## Вне MVP

Не реализуй регистрацию и личный кабинет, фильтры, детей и младенцев,
чат поддержки, админ-панель, альтернативные способы оплаты и многоязычность.

## Правила работы Copilot

- Сначала предложи план из 2–4 пунктов, затем внеси изменения.
- Работа ведётся поэтапно: разметка, состояние, валидация, тесты.
- Если для задачи не хватает стека, провайдера оплаты, формата данных или
  критериев карточки Trello, задавай один конкретный уточняющий вопрос.
- После изменения назови закрытый пункт требований и способ проверки.
- Ответы должны быть короткими и по шагам на русском.

## Критерии готовности

Задача считается готовой, когда выполнены критерии соответствующей карточки
Trello, а happy path от поиска до билета проходит без ошибок:

поиск → результаты → данные пассажира → оплата → подтверждение и билет.

Дополнительно должны быть обработаны все крайние случаи раздела выше.
